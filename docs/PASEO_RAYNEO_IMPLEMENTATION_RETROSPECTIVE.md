# Paseo × RayNeo 桥接实现与踩坑复盘

## 1. 目标与不可突破的边界

本批次目标是在 RayNeo AI 1.0.2 增强包中加入一条“眼镜语音 → MiniMax → Paseo/Codex”的完整链路，同时保留官方 App 原有连接能力。

明确边界：

- 不修改 Paseo daemon，不新增一套 Agent Server 注册和兼容协议。
- Turbo IO 直接作为 Paseo daemon 的平级客户端；Paseo App 继续负责完整历史、权限审批和高级操作。
- 只复用指定版本官方 APK 内的设备连接与传输能力，不把构建成功或 ACK 成功描述成镜片验收通过。
- 不把 API Key、daemon 密码、用户语音正文写入 APK、日志或文档。

## 2. 最终架构

```text
RayNeo 眼镜
  ⇅ 官方 CoreConnect / BLE / SPP
增强版 RayNeo AI（同包同进程）
  ├─ MiniMax ASR：整句语音识别
  ├─ MiniMax M3 意图路由：结合交互状态决定下一步
  ├─ MiniMax M3 Responses：普通问答、SSE 流式输出、web_search
  └─ Paseo WebSocket 客户端：会话、工作区、Codex query、任务状态
        ⇅
     原版 Paseo daemon
        ⇅
     Codex / Paseo App
```

增强包不接管 daemon 的业务实现，只调用 daemon 已有的 v1 WebSocket RPC。眼镜侧是短交互界面，手机 Paseo 是完整会话界面。

## 3. 已实现能力

### 3.1 语音和助手生命周期

- 普通唤醒后启动眼镜音频，手机侧解码 Opus、执行本地 VAD 和断句。
- ASR 完成后先通过 type 5 回显整句文字，再执行意图路由。
- 首句之后保持连续音频上行；模型回答期间仍监听语音。
- 检测到新讲话时发送语音状态切换，取消当前 ASR、意图或回答请求，并收取下一句，实现打断。
- 回答结束不再启动 10 秒强制关页计时；模型请求、流式增量、展示和新语音都会刷新 120 秒无活动保护。
- “退出”“退下”等指令主动结束眼镜助手，但不会关闭整个 Paseo 桥接模式。

### 3.2 意图路由

未处于确定性状态时，MiniMax M3 根据以下信息输出结构化意图：

- 当前 ASR 文本；
- 最近 10 条眼镜交互；
- 当前选择的 Paseo 会话和工作区；
- 是否正在等待停止确认；
- 是否正在等待为新会话选择工作区。

支持会话列表、翻页、详情、选择、当前会话、最后回复、工作区列表、新建会话、停止确认、退出、普通问答和 Codex query 等意图。

选择或新建 Codex 会话后，下一句属于确定性状态：完全跳过意图模型，ASR 完成后直接发送到当前 Codex 会话，避免把实际 query 错分到普通问答。

### 3.3 普通问答与流式显示

- 普通问题使用 MiniMax M3 Responses API。
- 天气、新闻、价格、行情等时效问题要求使用服务端 `web_search`；请求同时注入手机运行时日期、时间和时区。
- SSE 增量按节流频率发送到眼镜，避免过度刷新。
- 文本超过一屏后显示最新窗口，不再固定停留在第一屏。
- 完成时停留在最后一段，可用“上一段”“下一段”回看。

### 3.4 Paseo/Codex 桥接

- 通过 `ws://` 或 `wss://` 直连 daemon，支持可选密码。
- 支持列出和选择会话、查看详情、读取最后回复、停止任务。
- 支持列出 daemon 已登记的工作区，并在指定工作区新建 Codex 会话。
- Codex query 自动附加眼镜阅读约束：结论优先、短要点、避免表格和长代码。
- Codex 是异步任务。提交后的即时确认显示在助手页；最终执行结果作为普通通知发送，不追加到已经结束的助手回答流。

## 4. 关键问题与根因

### 4.1 手机不能使用电脑的 localhost

问题：手机填写 `localhost` 或 `127.0.0.1` 时，地址指向手机自身，不是电脑上的 daemon，表现为连接异常或 `IOException`。

处理：真实局域网连接使用 `ws://<电脑局域网地址>:6767/ws`，daemon 监听可达网卡并配置允许的 Host；仅在明确建立 `adb reverse` 时使用手机侧回环地址。

### 4.2 仅靠正则无法承受 ASR 同音错误

问题：例如“会话”可能被识别为“绘画”。继续堆叠正则只能覆盖已知错误，不能可靠处理省略、指代和多轮状态。

处理：模型成为未决状态下的唯一语义路由器，确定性状态则直接执行，不重复请求模型。正则解析器只保留为协议级工具和测试辅助，不承担主路由职责。

### 4.3 “意图识别失败”不是偶发网络问题

旧实现使用带推理输出的模型，且总输出上限较小。真机诊断抓到的失败响应是 HTTP 200，但 `finish_reason=length`、正文长度为 0，输出预算全部被 reasoning 消耗。客户端随后无法解析 JSON，最终只显示统一的“意图识别失败”。

处理：

- 意图模型切换为 MiniMax M3 Responses；
- 设置 `reasoning.effort=none`；
- 只要求输出短 JSON；
- 保留不含用户正文和凭据的结构化诊断字段，包括 HTTP 状态、响应状态、输出项数量和 token 数。

这次修复针对的是空正文根因，不是增加一个掩盖错误的本地降级分支。

### 4.4 直接聊天模型没有实时工具

问题：只调用普通 Chat Completions 时，模型会基于预训练知识回答天气和当前日期，看起来像“时间停在过去”。

处理：普通问答改用 MiniMax Responses 并声明服务端 `web_search` 工具；对明确的时效问题，只有检测到搜索工具执行证据后才展示答案，否则返回明确错误。

### 4.5 流式响应看起来停在第一屏

问题：网络端持续收到 SSE，但发送到眼镜的每次增量都截取累计文本的前 420 字节。第一屏填满后，后续内容虽然到达手机，镜片内容却不再变化。

处理：增量展示改为 UTF-8 安全的最新窗口；最终回答分页保存并定位到最后一段，避免结束时又跳回开头。

### 4.6 助手页过早退出有两套独立计时问题

第一处是回答完成后固定启动 10 秒退出计时，长流式展示和继续追问体验都会被截断。第二处是首轮“5 秒没听到语音”检查错误地延续到连续会话，可能把模型思考期间的正常静音当成录音失败。

处理：删除 10 秒完成计时；5 秒检查只用于初次收音；连续会话统一使用由所有有效活动续期的 120 秒保护。

### 4.7 打断不能只取消 HTTP

问题：如果回答期间停止眼镜音频上行，用户讲话根本到不了手机；只实现 `cancel()` 并不能形成可用打断。

处理：首句结束后继续保持录音和 Opus 输入，本地 VAD 在讲话起点取消当前前台请求并切换设备语音状态，然后继续完成新一句断句和 ASR。

### 4.8 Codex 完成结果不属于当前助手流

问题：Codex 可能运行数分钟。如果把完成结果追加到旧助手轮次，会遇到页面已经退出、轮次 ID 失效或状态机不再接受更新。

处理：助手页只显示“已发送”；Codex 最终结果走普通通知。需要完整历史和权限操作时直接打开 Paseo App。

## 5. 安全与脱敏

- MiniMax API Key 和 Paseo 密码由 AndroidKeyStore 加密，文件位于不参与备份的应用私有目录。
- 诊断日志不记录 Key、密码、录音、ASR 正文、用户 query 或模型回答正文。
- 网络错误对用户展示经过长度限制；诊断只记录类型和非敏感状态。
- 本文和其他交付文档只使用 `<电脑局域网地址>`、`/Users/USER/...` 等占位符。
- APK、官方反编译目录、签名密钥和其他厂商二进制均不提交仓库。

## 7. 构建与安装

```bash
cd /path/to/Unofficial-IO-Android
./enhancer/test/run.sh
./enhancer/build-enhanced-apk.sh /path/to/RayNeo_AI_1.0.2.apk
adb install --no-incremental -r \
  enhancer/build/output/RayNeo_AI_1.0.2-turbo-debug.apk
```

安装后先在官方入口完成连接，再打开 Turbo IO 保存 MiniMax Key、填写 `ws://<电脑局域网地址>:6767/ws`、测试 Paseo 连接并开启眼镜模式。

## 8. 当前仍需真机关注

- 镜片对连续 type 32 更新的视觉稳定性和刷新节奏；
- 长时间连续收音对耗电、蓝牙稳定性和官方功能切换的影响；
- 不同环境下本地 VAD 对远场、噪声和抢话的敏感度；
- 官方 APK 或 CoreConnect 升级后的反射符号、消息 ABI 和签名兼容性；
- Paseo daemon 协议升级后的客户端兼容性。

这些边界必须分别标注“源码验证”“主机测试”“APK 校验”“连接 ACK”或“镜片真机验证”，不能互相替代。
